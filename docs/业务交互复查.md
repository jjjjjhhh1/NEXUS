# 业务交互复查（2026-10-08）

本轮重点检查转账、定时转账、编辑、确认、取消、二次核验、密码设置、风险问卷和生日计划的状态切换，以及失败、重复提交和过期路径。

## 修复内容
1. 定时转账编辑保存回调读取块作用域外的 cadence / times，导致 ReferenceError。改为编辑器作用域变量。
2. 编辑框使用千分位金额，1000 元以上原样保存带逗号时后端金额校验失败。编辑值保留原始数字字符串。
3. 设置密码的子表单 submit 冒泡到转账核验表单。阻止冒泡并校验密码输入。
4. 核验及问卷连按 Enter 可重复进入请求，覆盖 busy 状态。增加提交门禁，busy 状态转换幂等。
5. 等待请求期间确认卡过期，恢复 busy 前的状态会重新启用过期按钮。过期标记同步禁用快照。
6. 确认卡替换后旧倒计时仍可能运行并修改界面。替换时停止旧倒计时，已移除卡片不再计时。
7. 二次核验失败后修改条款，旧核验表单仍可操作。编辑期间将旧核验表单设为 inert，取消时恢复。
8. 接口已有业务结果，但后续侧栏刷新失败会落入执行失败分支。把结果与数据刷新隔离，保留回执且提示无需重复提交。
9. 确认转账进入二次核验时误显示执行完成。按实际返回类型展示等待核验或完成。
10. 修改验证密码后仍显示及下发旧演示口令。前后端同步清除过时的演示凭据。
11. 一次性、每周等计划统一被标成每月。按实际 frequency 展示。
12. 生日计划请求失败时表单先被移除，丢失日期预算。成功收到回答后才关闭，失败重试复用原请求编号。
13. 交易列表变为空时仍保留旧记录。每次刷新先清空再绘制。
14. 网络中断提示错误地断言没有创建操作。改为最终结果尚未确认，提示先核对记录并沿用原编号重试。

此前的转账编辑保存/取消恢复按钮和相同响应强制刷新修复一并回归。

## 重跑方式
Python 测试建议在进程环境中设 NEXUS_LLM_API_KEY 为空、NEXUS_LLM_ENABLED=false，再运行 python -X utf8 -m pytest nexus/tests -q，避免真实模型造成网络依赖；不修改服务 .env。
浏览器测试需要开发环境安装 Playwright，并运行 node nexus/tests/browser/business-flows.cjs 和 node nexus/tests/browser/transfer-edit.cjs。
可通过 NEXUS_TEST_URL 指定服务地址，通过 NEXUS_TEST_BROWSER 指定本机浏览器可执行文件。

这是对主要业务链路与已知异常路径的回归，不代表穷尽所有输入、并发和外部服务故障。
