# 复合理财规划改造与本地验收

## 架构
安全门卫 → 模型意图/结构化 FinancialTaskPlan → 金额与期限逐字来源核验 → 目标测算、资产诊断、现金流、风控、产品准入、原目标影响模块 → 一致性汇总 → 原有输出合规层。

模型可建议模块，但不能跳过强制风控，不能执行交易，不能编造本金或改变用户明确说出的金额/期限。无模型时只解析明确的金额、期限和利润/储蓄目标；缺失或多目标歧义先追问。

## 当前目标政策
- 当前消息中的目标优先，原档案目标降级为背景；分析不自动修改档案。
- 新目标没有确认前，不释放原目标资金或生成对应产品购买计划。
- 本金按现金扣除应急金保守测算，不把投资持仓假定为立即可赎回，也不将未来收入当作已拥有本金。
- 利润目标收益率 = 目标利润 / 测算本金，显示为期内总收益率，非年化。
- 月均所需收益率超过 1% 为本次实现的保守审核阈值；不代表低于阈值即可实现，所有利润目标均暂缓产品推荐。
- 收益承诺、借钱投资、R3+ 请求触发禁止推荐；当前目标期限重新参与风险上限计算。
- 前端依次显示当前结论、测算依据、替代方向、原目标确认问题。

## 模块契约
FinancialTaskPlan：objective、evidence、amount、months、kind、confidence、modules。
模块结果：status + data。orchestration 字段记录来源、置信度、模块列表、结果、目标冲突和一致性状态。trace 解释路由、计算与风控依据，日志不记录用户原始财务数据。
